# 验证

需要 Windows 和 .NET 10 SDK，在项目根目录执行。

## 无系统设置写入的回归检查

```powershell
dotnet run --project tests/DuoLaBox.RegressionVerification
```

覆盖清理页面忙碌状态、空列表、部分/全部清理结果，Hosts 编辑及保存基线，重叠重命名失败回滚、正常执行、文件名交换和暂存阶段失败。

另覆盖已校验任务快照及篡改拒绝，原子文件新建/替换、锁定目标和编码失败时保留原文件、临时文件回收，无效清理规则隔离、同目录多规则匹配与去重、目录递归、根路径、遍历取消和过期扫描预算。扫描只读取新建临时目录，不执行清理。

并发检查覆盖忙碌状态下文件参数排队及快照、重复任务拒绝、重命名确认取消、Hosts/主题/启动设置控件恢复，以及参数转发确认、超长与无效消息、慢连接超时、监听关闭和互斥锁接管。IPC 使用独立的随机测试名称，不向正在运行的主应用发送参数。

扫描的时间预算与取消采用协作检查，包含目录及文件遍历；无法强制中断已经阻塞的单次操作系统文件调用。

清理页面仅使用虚构候选项，不删除真实缓存；Hosts 只操作编辑控件，不读取或保存系统 Hosts；文件测试只操作新建的唯一临时目录，结束后移除该目录。不启动 DuoLaBox 主应用，不注册右键菜单，不修改启动项或剪贴板。

## 剪贴板检查（会替换剪贴板内容）

```powershell
dotnet run --project tests/DuoLaBox.ClipboardVerification -- --allow-clipboard-write
```

覆盖 UI 线程和后台调用的文本写入、Unicode 和多行文本回读。必须显式授权剪贴板写入，不保证恢复原来的剪贴板内容。

## 主应用手动检查

- 编辑 Hosts 后切换页面再返回：编辑内容应保持。
- 点击重新读取：有未保存修改时应确认，选择“否”应保留编辑。
- 保存期间继续编辑：保存完成不应覆盖后续编辑，保存和重新读取按钮应禁用。
- 文件处理或重命名确认期间，从资源管理器继续添加文件：当前任务不应改变，完成或取消后自动添加。队列最多保留 64 个请求，超出时提示重新添加。
- 主题切换、启动设置或右键菜单更新期间，相关控件应禁用；更新完成恢复。主题切换失败时恢复实际系统模式。
- 文件处理、Hosts 保存和设置更新期间请求退出：应提示等待完成或取消；关闭到托盘仍可正常工作。
- 分别普通启动和 `--silent` 启动，检查初始化；静默启动后再显示窗口，不应重复加载页面设置。

主应用启动会同步右键菜单，配置启用时也会更新启动项；这部分请在允许修改这些用户设置的 Windows 环境中验证。

单实例通信现在按 Windows 用户和会话隔离，使用限长帧和接收确认；升级时应先退出旧版本，旧版通信名称与协议不兼容。确认仅表示参数已交给接收处理程序，不表示文件任务已经执行成功。

## 原有集成验证程序

`DuoLaBox.Verification` 包含真实注册表写入，目前仍会注册右键菜单且不恢复之前状态，不应作为无副作用回归检查运行。该问题留待后续测试隔离批次修复。
